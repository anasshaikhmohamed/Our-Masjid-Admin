user
admin
super_admin

6. RLS SECURITY
==================================================

Enable RLS on all relevant application tables.

PUBLIC READ:

Anonymous/authenticated users can read:

- published categories
- published, non-hidden Masjids
- published, non-hidden projects
- public Masjid media
- public project media
- published home slides
- public Masjid documents where is_private=false
- public project documents where is_private=false
- public project expense information

NORMAL AUTHENTICATED USER:

Can:
- read own profile
- create own donation intent with status=initiated
- read own donation intents

Cannot:
- change role
- manage content
- publish content
- hide content
- change fundraising totals
- change donation status
- access private documents
- access audit logs
- access app settings
- perform admin operations

ADMIN:

Can manage normal application content according to role.

SUPER_ADMIN:

Can:
- manage admin roles
- access private documents
- manage settings
- access audit logs
- manage sensitive admin data
- manage Storage objects

IMPORTANT:

Prevent RLS recursion and privilege escalation.

Use a secure SECURITY DEFINER role-checking helper/function where appropriate.

Do not create a policy that allows a user to promote themselves to admin or super_admin.

Audit log creation should be trusted/server-side and not freely client-controlled.
